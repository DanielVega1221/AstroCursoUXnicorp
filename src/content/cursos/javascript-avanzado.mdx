<section class="mb-16">
  <h2>Closures (Clausuras)</h2>
  
  <div class="bg-gradient-to-r from-purple-50 to-pink-50 dark:from-purple-900/20 dark:to-pink-900/20 p-6 rounded-lg mb-6">
    <h3 class="text-lg font-semibold mb-4">🔒 ¿Qué es un Closure?</h3>
    
    <p class="mb-4">
      Un <strong>closure</strong> es cuando una función "recuerda" las variables de donde fue creada, 
      incluso después de que la función externa haya terminado.
    </p>
    
    <div class="bg-white dark:bg-gray-800 p-4 rounded mb-4">
      <p class="font-semibold mb-3">🎒 Analogía de la mochila:</p>
      <p class="text-sm mb-2">
        Imagina que una función es una persona que va de viaje. Antes de irse, mete cosas en su mochila.
      </p>
      <ul class="text-sm space-y-1">
        <li>La función "sale de viaje" (se ejecuta)</li>
        <li>Lleva su mochila con variables (closure)</li>
        <li>Aunque la casa (función externa) ya no existe, la persona sigue teniendo su mochila</li>
        <li>Puede usar esas variables cuando quiera</li>
      </ul>
    </div>
    
    <p class="text-sm">
      Los closures son útiles para crear <strong>datos privados</strong> - variables que solo una función específica puede modificar.
    </p>
  </div>
  
  <h3>Ejemplo: Contador Privado</h3>
  
  <p class="mb-4">
    Vamos a crear un contador donde el número está "protegido" - solo las funciones que devolvemos pueden modificarlo:
  </p>
  
  <CodeBlock
    language="javascript"
    filename="contador.js"
    code={`function crearContador() {
  let contador = 0;
  
  return {
    incrementar: () => ++contador,
    obtener: () => contador
  };
}

const miContador = crearContador();
console.log(miContador.incrementar()); // 1
console.log(miContador.incrementar()); // 2
console.log(miContador.obtener());     // 2`}
  />
  
  <div class="bg-gray-50 dark:bg-gray-800 p-6 rounded-lg mt-6">
    <h4 class="text-lg font-semibold mb-4">🔍 ¿Qué está pasando aquí?</h4>
    
    <div class="space-y-4">
      <div class="border-l-4 border-purple-500 pl-4">
        <code class="text-sm font-semibold">let contador = 0;</code>
        <p class="text-sm mt-2">
          Esta variable vive DENTRO de <code>crearContador</code>. Normalmente desaparecería cuando la función termina.
        </p>
      </div>
      
      <div class="border-l-4 border-blue-500 pl-4">
        <code class="text-sm font-semibold">{`return { incrementar: ..., obtener: ... }`}</code>
        <p class="text-sm mt-2">
          Devolvemos un objeto con dos funciones. Estas funciones "recuerdan" la variable <code>contador</code> (closure).
        </p>
      </div>
      
      <div class="border-l-4 border-green-500 pl-4">
        <code class="text-sm font-semibold">miContador.incrementar()</code>
        <p class="text-sm mt-2">
          Aunque <code>crearContador</code> ya terminó, la función <code>incrementar</code> todavía puede acceder y modificar <code>contador</code>.
        </p>
      </div>
    </div>
    
    <div class="bg-yellow-50 dark:bg-yellow-900/20 p-4 rounded mt-4">
      <p class="font-semibold mb-2">💡 ¿Por qué es útil?</p>
      <p class="text-sm">
        No puedes hacer <code>miContador.contador = 999</code> y romper el contador. 
        La variable está "privada" - solo las funciones que devolviste pueden cambiarla. 
        Es como tener una caja fuerte donde solo ciertas llaves funcionan.
      </p>
    </div>
  </div>
  
  <h3 class="mt-8">Otro Ejemplo: Generador de Saludo Personal</h3>
  
  <CodeBlock
    language="javascript"
    code={`function crearSaludo(nombre) {
  // Esta variable queda "capturada" en el closure
  return function(mensaje) {
    return \`\${mensaje}, \${nombre}!\`;
  };
}

const saludoAna = crearSaludo('Ana');
const saludoCarlos = crearSaludo('Carlos');

console.log(saludoAna('Hola'));     // "Hola, Ana!"
console.log(saludoAna('Buenos días')); // "Buenos días, Ana!"
console.log(saludoCarlos('Hola'));   // "Hola, Carlos!"

// Cada función "recuerda" su propio nombre`}
  />
  
  <div class="bg-blue-50 dark:bg-blue-900/20 p-4 rounded mt-4">
    <p class="text-sm">
      Cada vez que llamas <code>crearSaludo</code>, creas un nuevo closure con su propio <code>nombre</code>. 
      <code>saludoAna</code> recuerda "Ana" y <code>saludoCarlos</code> recuerda "Carlos".
    </p>
  </div>
</section>

<section class="mb-16">
  <h2>Event Loop (Bucle de Eventos)</h2>
  
  <div class="bg-gradient-to-r from-orange-50 to-red-50 dark:from-orange-900/20 dark:to-red-900/20 p-6 rounded-lg mb-6">
    <h3 class="text-lg font-semibold mb-4">🔄 ¿Qué es el Event Loop?</h3>
    
    <p class="mb-4">
      El <strong>Event Loop</strong> es el mecanismo que permite a JavaScript hacer varias cosas "al mismo tiempo", 
      aunque realmente JavaScript solo puede hacer UNA cosa a la vez.
    </p>
    
    <div class="bg-white dark:bg-gray-800 p-4 rounded mb-4">
      <p class="font-semibold mb-3">🍕 Analogía de la pizzería:</p>
      <p class="text-sm mb-3">
        Imagina una pizzería con un solo cocinero (JavaScript es single-thread):
      </p>
      <div class="space-y-2 text-sm">
        <div class="flex gap-3">
          <span>1️⃣</span>
          <p>El cocinero toma un pedido y mete la pizza al horno (operación async)</p>
        </div>
        <div class="flex gap-3">
          <span>2️⃣</span>
          <p>Mientras el horno cocina (espera), el cocinero toma OTRO pedido</p>
        </div>
        <div class="flex gap-3">
          <span>3️⃣</span>
          <p>Cuando suena el timer del horno, vuelve y saca la primera pizza</p>
        </div>
        <div class="flex gap-3">
          <span>4️⃣</span>
          <p>Continúa con lo siguiente</p>
        </div>
      </div>
      <p class="text-sm mt-3 italic">
        El cocinero nunca espera sin hacer nada. Siempre está ocupado con algo.
      </p>
    </div>
    
    <p class="text-sm">
      JavaScript funciona igual: no se queda esperando. Inicia tareas lentas (fetch, timers) 
      y sigue ejecutando código. Cuando las tareas terminan, vuelve a ellas.
    </p>
  </div>
  
  <h3>Ejemplo Clásico: El Orden de Ejecución</h3>
  
  <p class="mb-4">
    Este ejemplo confunde a todos al principio. Veamos por qué sale en este orden:
  </p>
  
  <CodeBlock
    language="javascript"
    code={`console.log('1');

setTimeout(() => {
  console.log('2');
}, 0);

Promise.resolve().then(() => {
  console.log('3');
});

console.log('4');

// Salida: 1, 4, 3, 2`}
  />
  
  <div class="bg-gray-50 dark:bg-gray-800 p-6 rounded-lg mt-6">
    <h4 class="text-lg font-semibold mb-4">🔍 Explicación paso a paso:</h4>
    
    <div class="space-y-4">
      <div class="bg-blue-50 dark:bg-blue-900/30 p-4 rounded">
        <p class="font-semibold text-blue-600 mb-2">Paso 1: <code>console.log('1')</code></p>
        <p class="text-sm">Esto es código síncrono normal. Se ejecuta inmediatamente.</p>
        <p class="text-xs mt-1 italic">Salida: "1"</p>
      </div>
      
      <div class="bg-yellow-50 dark:bg-yellow-900/30 p-4 rounded">
        <p class="font-semibold text-yellow-700 dark:text-yellow-300 mb-2">Paso 2: <code>setTimeout</code></p>
        <p class="text-sm mb-2">
          JavaScript dice: "Ok, ejecuta esto después. Ahora sigo con lo siguiente."
        </p>
        <p class="text-xs">Este callback va a la <strong>Task Queue</strong> (cola de tareas).</p>
        <p class="text-xs italic mt-1">No imprime nada todavía</p>
      </div>
      
      <div class="bg-purple-50 dark:bg-purple-900/30 p-4 rounded">
        <p class="font-semibold text-purple-600 mb-2">Paso 3: <code>Promise.resolve().then()</code></p>
        <p class="text-sm mb-2">
          JavaScript dice: "Ok, esto también es async. Lo guardo."
        </p>
        <p class="text-xs">Este callback va a la <strong>Microtask Queue</strong> (cola de microtareas).</p>
        <p class="text-xs italic mt-1">No imprime nada todavía</p>
      </div>
      
      <div class="bg-green-50 dark:bg-green-900/30 p-4 rounded">
        <p class="font-semibold text-green-600 mb-2">Paso 4: <code>console.log('4')</code></p>
        <p class="text-sm">Código síncrono normal. Se ejecuta inmediatamente.</p>
        <p class="text-xs mt-1 italic">Salida: "4"</p>
      </div>
      
      <div class="bg-purple-50 dark:bg-purple-900/30 p-4 rounded">
        <p class="font-semibold text-purple-600 mb-2">Paso 5: Event Loop revisa Microtask Queue</p>
        <p class="text-sm mb-2">
          Ya no hay código síncrono. El Event Loop busca en la <strong>Microtask Queue primero</strong>.
        </p>
        <p class="text-xs">Encuentra el Promise y lo ejecuta.</p>
        <p class="text-xs italic mt-1">Salida: "3"</p>
      </div>
      
      <div class="bg-yellow-50 dark:bg-yellow-900/30 p-4 rounded">
        <p class="font-semibold text-yellow-700 dark:text-yellow-300 mb-2">Paso 6: Event Loop revisa Task Queue</p>
        <p class="text-sm mb-2">
          Ahora revisa la Task Queue y encuentra el setTimeout.
        </p>
        <p class="text-xs italic mt-1">Salida: "2"</p>
      </div>
    </div>
    
    <div class="bg-gradient-to-r from-red-50 to-orange-50 dark:from-red-900/20 dark:to-orange-900/20 p-4 rounded mt-6">
      <h4 class="font-semibold mb-3">🎯 Regla clave:</h4>
      <ol class="text-sm space-y-2">
        <li><strong>1.</strong> Ejecuta todo el código síncrono primero</li>
        <li><strong>2.</strong> Luego ejecuta la Microtask Queue (Promises)</li>
        <li><strong>3.</strong> Finalmente ejecuta la Task Queue (setTimeout, setInterval)</li>
      </ol>
      <p class="text-xs mt-3 italic">
        Por eso los Promises siempre se ejecutan ANTES que los setTimeout, 
        incluso si el setTimeout tiene delay de 0.
      </p>
    </div>
  </div>
  
  <h3 class="mt-8">Ejemplo Práctico: Fetch de API</h3>
  
  <CodeBlock
    language="javascript"
    code={`console.log('Empezando...');

fetch('https://api.example.com/data')
  .then(response => response.json())
  .then(data => {
    console.log('Datos recibidos:', data);
  });

console.log('Continuando con otras cosas...');

// Salida:
// "Empezando..."
// "Continuando con otras cosas..."
// "Datos recibidos: {...}" (después de que llega la respuesta)`}
  />
  
  <div class="bg-blue-50 dark:bg-blue-900/20 p-4 rounded mt-4">
    <p class="font-semibold mb-2">💡 ¿Qué pasa aquí?</p>
    <p class="text-sm mb-2">
      JavaScript NO se queda esperando a que llegue la respuesta del servidor. 
      Continúa ejecutando código (imprime "Continuando...") y cuando la respuesta llega, 
      ejecuta el <code>.then()</code>.
    </p>
    <p class="text-sm">
      Esto es lo que hace que las páginas web sean rápidas y responsivas. 
      Si JavaScript se quedara esperando cada fetch, la página se congelaría.
    </p>
  </div>
</section>
  
<section class="mb-16">
  <h2>Async/Await - Sintaxis Moderna</h2>
  
  <div class="bg-gradient-to-r from-green-50 to-emerald-50 dark:from-green-900/20 dark:to-emerald-900/20 p-6 rounded-lg mb-6">
    <h3 class="text-lg font-semibold mb-4">✨ Una forma más limpia de escribir código asíncrono</h3>
    
    <p class="mb-4">
      <code>async/await</code> es "azúcar sintáctica" sobre Promises. Hace que el código asíncrono 
      se vea como código normal, más fácil de leer.
    </p>
  </div>
  
  <h3>Comparación: Promises vs Async/Await</h3>
  
  <div class="grid md:grid-cols-2 gap-4 mb-6">
    <div class="card bg-yellow-50 dark:bg-yellow-900/20">
      <p class="font-semibold text-yellow-700 dark:text-yellow-300 mb-3">Con Promises (viejo):</p>
      <CodeBlock
        language="javascript"
        code={`fetch('/api/user')
  .then(res => res.json())
  .then(user => {
    return fetch(\`/api/posts/\${user.id}\`);
  })
  .then(res => res.json())
  .then(posts => {
    console.log(posts);
  })
  .catch(error => {
    console.error(error);
  });`}
      />
    </div>
    
    <div class="card bg-green-50 dark:bg-green-900/20">
      <p class="font-semibold text-green-600 mb-3">Con Async/Await (moderno):</p>
      <CodeBlock
        language="javascript"
        code={`async function obtenerPosts() {
  try {
    const resUser = await fetch('/api/user');
    const user = await resUser.json();
    
    const resPosts = await fetch(\`/api/posts/\${user.id}\`);
    const posts = await resPosts.json();
    
    console.log(posts);
  } catch (error) {
    console.error(error);
  }
}`}
      />
    </div>
  </div>
  
  <div class="bg-blue-50 dark:bg-blue-900/20 p-4 rounded">
    <p class="font-semibold mb-2">✅ Ventajas de async/await:</p>
    <ul class="text-sm space-y-1">
      <li>Más fácil de leer - parece código normal</li>
      <li>Mejor manejo de errores con try/catch</li>
      <li>Más fácil de debuggear</li>
      <li>Menos anidación (no más "callback hell")</li>
    </ul>
  </div>
</section>
