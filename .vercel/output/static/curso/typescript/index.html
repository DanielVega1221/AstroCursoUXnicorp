Módulo 8

TypeScript para Astro y React

Añade type safety a tus proyectos para detectar errores antes de tiempo.

¿Qué es TypeScript y por qué existe?

🤔 El problema con JavaScript normal

Imagina que estás escribiendo una carta a mano. Puedes escribir lo que quieras, pero si cometes un error de ortografía, nadie te avisa hasta que alguien la lee y te dice "oye, aquí hay un error".

❌ JavaScript normal:

let edad = "25";
console.log(edad + 5); // Resultado: "255" 🤯

JavaScript pensó que querías unir textos, no sumar números. ¡Error silencioso!

✅ Con TypeScript:

let edad: number = "25"; // ❌ ERROR inmediato
// TypeScript te dice: "¡Espera! edad debe ser un número, no texto"

Te atrapa el error ANTES de que causes problemas. Como un corrector ortográfico.

📝 ¿Qué es TypeScript?

TypeScript es JavaScript + un sistema de tipos. Es como JavaScript con un asistente que revisa tu código y te avisa de errores mientras escribes, no cuando ya está publicado.

Fue creado por Microsoft. Todo código TypeScript se convierte en JavaScript al final, así que funciona en todos los navegadores.

🎯 Analogía perfecta:

  • 📝 JavaScript: Escribir sin corrector ortográfico - rápido pero peligroso
  • ✅ TypeScript: Escribir con corrector que subraya errores en rojo - te ayuda a evitar problemas

Tipos Básicos

🏷️ ¿Qué es un "tipo"?

Un tipo es como una etiqueta que le pones a una variable para decir qué clase de información guarda.

📝 string

Texto - palabras, frases

"Hola", "Ana", "123"

🔢 number

Números - enteros, decimales

42, 3.14, -10

✅ boolean

Verdadero o Falso

true, false

En TypeScript, declaras el tipo de una variable con dos puntos : después del nombre:

🔍 Explicación línea por línea:

const nombre: string = "Ana";

nombre es una variable que SOLO puede guardar texto (string). Si intentas poner un número, TypeScript te detiene.

const numeros: number[] = [1, 2, 3];

numeros es un array (lista) que SOLO puede contener números. Los corchetes [] significan "array de".

También puedes escribirlo como: Array<number> - es lo mismo, dos formas de decir lo mismo.

interface Usuario { ... }

Una interface es como un molde o plantilla. Define la forma que debe tener un objeto.

Piensa en ello como un formulario: "Todo Usuario debe tener nombre (texto), edad (número), y opcionalmente email".

email?: string;

El signo ? significa opcional. Este campo puede existir o no. Sin el ?, TypeScript te obligaría a incluirlo siempre.

💡 ¿Por qué usar tipos?

Imagina que tienes una función que suma dos números. Sin tipos, alguien podría pasarle texto por accidente:

Sin TypeScript:

sumar("5", "3")

Resultado: "53" 🤦 (unió texto)

Con TypeScript:

sumar("5", "3")

❌ ERROR: "Los parámetros deben ser números"

Props Tipadas en React

🎁 ¿Qué son las Props?

Props (abreviatura de "properties" = propiedades) son como los argumentos o parámetros que le pasas a un componente de React.

🎯 Analogía:

Imagina que un componente es una máquina de hacer sándwiches. Las props son los ingredientes que le das:

  • • Le das: pan, jamón, queso (props)
  • • La máquina: hace el sándwich (componente)
  • • Obtienes: un sándwich de jamón y queso (resultado)

Sin TypeScript, la máquina aceptaría cualquier cosa (¿arena? ¿zapatos?). Con TypeScript, defines exactamente qué ingredientes acepta.

🔍 Desglosando el código:

interface ButtonProps {

Definimos la "receta" de ingredientes que acepta nuestro botón. Es como escribir en la máquina: "Solo acepto estos ingredientes específicos".

text: string;

El botón DEBE recibir un texto (string). Sin texto, no hay botón. Es obligatorio.

Ejemplo: text="Enviar"

onClick: () => void;

Una función que se ejecuta cuando haces clic. () => void significa: "una función que no recibe parámetros y no devuelve nada".

Ejemplo: onClick={}() => console.log('Click!')}}

variant?: 'primary' | 'secondary';

El ? lo hace opcional. El | significa "o". Solo puede ser "primary" o "secondary", nada más.

Esto se llama "Union Type":

Es como decir: "puede ser rojo O azul, pero nunca verde"

variant = 'primary'

Valor por defecto. Si no le pasas variant, usa 'primary' automáticamente. Es como un ingrediente que ya viene incluido si no especificas otro.

🎓 Resumen: ¿Por qué tipar las props?

  • ✅ Previene errores: No puedes pasar datos incorrectos
  • ✅ Auto-completado: Tu editor te muestra qué props existen mientras escribes
  • ✅ Documentación automática: Otros desarrolladores ven exactamente qué necesita el componente
  • ✅ Refactorización segura: Si cambias una prop, TypeScript te avisa dónde más debes actualizar

📘 TypeScript Cheat Sheet

Tipos Básicos

let nombre: string = "Ana";

let edad: number = 25;

let activo: boolean = true;

let nulo: null = null;

let indefinido: undefined;

let cualquiera: any; - ❌ Evitar

Arrays y Objetos

let nums: number[] = [1, 2, 3];

let user: { name: string; age: number; }

let mixed: (string | number)[];

Interfaces

interface Usuario {
  nombre: string;
  edad: number;
  email?: string;  // Opcional
  readonly id: number;  // Solo lectura
}

const usuario: Usuario = {
  nombre: "Ana",
  edad: 25,
  id: 1
};

Type Aliases

type ID = string | number;
type Estado = "pendiente" | "completado" | "cancelado";

let taskId: ID = 123;
let status: Estado = "pendiente";

Funciones

function sumar(a: number, b: number): number {
  return a + b;
}

const restar = (a: number, b: number): number => a - b;

Union Types

type Respuesta = string | number | boolean;

function procesar(data: string | number) {
  if (typeof data === "string") {
    return data.toUpperCase();
  }
  return data * 2;
}

Generics

function primero<T>(arr: T[]): T | undefined {
  return arr[0];
}

const num = primero([1, 2, 3]);  // number
const str = primero(["a", "b"]);  // string

Utility Types

Partial<User> - Todas las props opcionales

Required<User> - Todas las props requeridas

Pick<User, 'name' | 'email'> - Solo ciertas props

Omit<User, 'password'> - Excluir props

Readonly<User> - Solo lectura

  text: string;
  onClick?: () => void;

  disabled?: boolean;
