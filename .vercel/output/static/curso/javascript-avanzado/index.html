Closures (Clausuras)

🔒 ¿Qué es un Closure?

Un closure es cuando una función "recuerda" las variables de donde fue creada, incluso después de que la función externa haya terminado.

🎒 Analogía de la mochila:

Imagina que una función es una persona que va de viaje. Antes de irse, mete cosas en su mochila.

  • La función "sale de viaje" (se ejecuta)
  • Lleva su mochila con variables (closure)
  • Aunque la casa (función externa) ya no existe, la persona sigue teniendo su mochila
  • Puede usar esas variables cuando quiera

Los closures son útiles para crear datos privados - variables que solo una función específica puede modificar.

Vamos a crear un contador donde el número está "protegido" - solo las funciones que devolvemos pueden modificarlo:

🔍 ¿Qué está pasando aquí?

Esta variable vive DENTRO de crearContador. Normalmente desaparecería cuando la función termina.

Devolvemos un objeto con dos funciones. Estas funciones "recuerdan" la variable contador (closure).

miContador.incrementar()

Aunque crearContador ya terminó, la función incrementar todavía puede acceder y modificar contador.

💡 ¿Por qué es útil?

No puedes hacer miContador.contador = 999 y romper el contador. La variable está "privada" - solo las funciones que devolviste pueden cambiarla. Es como tener una caja fuerte donde solo ciertas llaves funcionan.

Event Loop (Bucle de Eventos)

🔄 ¿Qué es el Event Loop?

El Event Loop es el mecanismo que permite a JavaScript hacer varias cosas "al mismo tiempo", aunque realmente JavaScript solo puede hacer UNA cosa a la vez.

🍕 Analogía de la pizzería:

Imagina una pizzería con un solo cocinero (JavaScript es single-thread):

1️⃣

El cocinero toma un pedido y mete la pizza al horno (operación async)

2️⃣

Mientras el horno cocina (espera), el cocinero toma OTRO pedido

3️⃣

Cuando suena el timer del horno, vuelve y saca la primera pizza

4️⃣

Continúa con lo siguiente

El cocinero nunca espera sin hacer nada. Siempre está ocupado con algo.

JavaScript funciona igual: no se queda esperando. Inicia tareas lentas (fetch, timers) y sigue ejecutando código. Cuando las tareas terminan, vuelve a ellas.

Ejemplo Clásico: El Orden de Ejecución

Este ejemplo confunde a todos al principio. Veamos por qué sale en este orden:

9});

11console.log(&#039;4&#039;);
12 
13500 italic">// Salida: 1, 4, 3, 2

🔍 Explicación paso a paso:

Paso 1: console.log('1')

Esto es código síncrono normal. Se ejecuta inmediatamente.

Salida: "1"

Paso 2: setTimeout

JavaScript dice: "Ok, ejecuta esto después. Ahora sigo con lo siguiente."

Este callback va a la Task Queue (cola de tareas).

No imprime nada todavía

Paso 3: Promise.resolve().then()

JavaScript dice: "Ok, esto también es async. Lo guardo."

Este callback va a la Microtask Queue (cola de microtareas).

No imprime nada todavía

Paso 4: console.log('4')

Código síncrono normal. Se ejecuta inmediatamente.

Salida: "4"

Paso 5: Event Loop revisa Microtask Queue

Ya no hay código síncrono. El Event Loop busca en la Microtask Queue primero.

Encuentra el Promise y lo ejecuta.

Salida: "3"

Paso 6: Event Loop revisa Task Queue

Ahora revisa la Task Queue y encuentra el setTimeout.

Salida: "2"

🎯 Regla clave:

  1. 1. Ejecuta todo el código síncrono primero
  2. 2. Luego ejecuta la Microtask Queue (Promises)
  3. 3. Finalmente ejecuta la Task Queue (setTimeout, setInterval)

Por eso los Promises siempre se ejecutan ANTES que los setTimeout, incluso si el setTimeout tiene delay de 0.

💡 ¿Qué pasa aquí?

JavaScript NO se queda esperando a que llegue la respuesta del servidor. Continúa ejecutando código (imprime "Continuando...") y cuando la respuesta llega, ejecuta el .then().

Esto es lo que hace que las páginas web sean rápidas y responsivas. Si JavaScript se quedara esperando cada fetch, la página se congelaría.

✨ Una forma más limpia de escribir código asíncrono

async/await es "azúcar sintáctica" sobre Promises. Hace que el código asíncrono se vea como código normal, más fácil de leer.
